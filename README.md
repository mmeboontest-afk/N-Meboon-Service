# N'Meboon Menu Link (Web Service version)

เว็บลิงก์รวมโซเชียลของ N'Meboon พร้อมวิดีโอทรานซิชันตอนเปลี่ยนหน้า (มีเสียง)
และการ์ดแสดงยอดผู้ติดตาม + วิดีโอล่าสุดจาก YouTube

## โครงสร้างไฟล์
```
server.js            เซิร์ฟเวอร์ Express (จุดเริ่มโปรแกรม) + /api/youtube
package.json         รายชื่อ dependency + คำสั่ง start
public/
  index.html          หน้าหลัก (Youtube, Discord, Tiktok, Menu Link, การ์ด YouTube)
  menu.html           หน้าเมนูอื่นๆ (Roblox, Suno, Facebook, กลับหน้าหลัก)
  style.css           สไตล์ทั้งเว็บ
  script.js           ระบบทรานซิชันวิดีโอ + อนิเมชันปุ่ม + ดึงข้อมูล YouTube
  assets/             ไฟล์วิดีโอทรานซิชัน (.mp4 / .webm มีเสียงแล้ว)
```

## วิธี deploy บน Render (Web Service)

1. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ขึ้น GitHub repo **โดยให้ `server.js` และ `package.json` อยู่ที่ root ของ repo เลย** (ห้ามมีโฟลเดอร์ครอบอีกชั้น เช่น repo/nmeboon-website/server.js — ถ้า push ผิดชั้นแบบนี้ Render จะหา `package.json` ไม่เจอและเว็บจะขึ้น "Not Found")
2. เข้า https://dashboard.render.com → **New** → **Web Service**
3. เชื่อมกับ repo ที่เพิ่งสร้าง
4. ตั้งค่า:
   - **Runtime:** Node
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
5. ไปที่แท็บ **Environment** เพิ่มตัวแปร (ดูวิธีขอ API key ด้านล่าง):
   - `YOUTUBE_API_KEY` = ใส่คีย์ที่ขอมา
   - `YOUTUBE_HANDLE` = `NongMeboon` (ใส่หรือไม่ใส่ก็ได้ ค่าเริ่มต้นเป็นอันนี้อยู่แล้ว)
6. กด **Create Web Service** / **Manual Deploy** รอ build เสร็จ

## แก้ปัญหา "Not Found"
อาการนี้เกือบทั้งหมดเกิดจาก 1 ใน 3 ข้อนี้:
1. **โครงสร้างโฟลเดอร์ผิดชั้น** — `server.js` ต้องอยู่ที่ root ของ repo ไม่ใช่ในโฟลเดอร์ย่อย (เช็คได้จากแท็บ "Root Directory" ในหน้า Settings ของ service ว่าตรงกับที่ไฟล์อยู่จริงไหม)
2. **ตั้ง Service ผิดประเภท** — ถ้าสร้างเป็น "Static Site" ไว้ก่อนหน้านี้ แล้วมาใส่ `server.js`/`package.json` เพิ่ม จะไม่ทำงาน ต้องลบแล้วสร้างใหม่เป็น **Web Service** เท่านั้น
3. **Deploy ล้มเหลว** — เข้าไปที่แท็บ **Logs** ของ service ดูว่ามี error สีแดงตอน build หรือตอน start ไหม (เช่น `Cannot find module 'express'` แปลว่า build ไม่ผ่าน หรือลืมกด Manual Deploy หลังแก้โค้ด)

ถ้าเช็คแล้วยังไม่หาย ส่ง screenshot ของแท็บ **Logs** มาให้ดูได้เลย จะวิเคราะห์ให้ตรงจุดกว่านี้

## เรื่องเสียงในวิดีโอทรานซิชัน
ใส่เสียงกลับเข้าไปในวิดีโอให้แล้ว แต่มีข้อจำกัดจากตัวเบราว์เซอร์เองที่ควรรู้ไว้:
- **ตอนกดปุ่มเปลี่ยนหน้าในเว็บเดียวกัน** (เช่น "Menu Link | Other") **เสียงจะเล่นแน่นอน** เพราะเป็นการกดของผู้ใช้จริง เบราว์เซอร์อนุญาต
- **ตอนเปิดเว็บครั้งแรก/เข้าใหม่ตรงๆ** เบราว์เซอร์ (Chrome, Safari, Firefox ทุกตัว) จะ**บล็อกไม่ให้วิดีโอเล่นเสียงอัตโนมัติ**โดยไม่มีการโต้ตอบจากผู้ใช้ก่อน — นี่คือกฎของเบราว์เซอร์เอง ไม่ใช่ข้อจำกัดของโค้ด ไม่มีเว็บไหนเลี่ยงได้ 100%
- เพื่อแก้ปัญหานี้ ได้ทำปุ่ม 🔈 เล็กๆ มุมขวาล่างไว้ให้ ถ้าเบราว์เซอร์บล็อกเสียง วิดีโอจะยังเล่นภาพต่อได้ปกติ (แค่ไม่มีเสียง) แล้วปุ่มนี้จะโผล่มาให้กดเปิดเสียงเอง

## เรื่องพื้นหลังโปร่งใส (สำคัญ ขอชี้แจงตรงๆ)
เช็คไฟล์วิดีโอต้นฉบับที่ส่งมาอีกรอบแล้ว พบว่า**ไฟล์ไม่มีช่องอัลฟ่า (alpha channel) อยู่เลย** — คือมันเป็นวิดีโอทึบแสงปกติ (พื้นหลังจริงๆ เป็นสีดำ/สีขาวสลับกันไปตามแต่ละช่วง) ไม่ใช่ไฟล์โปร่งใสตั้งแต่ต้น แม้จะตั้งใจเลือกออปชันโปร่งใสตอน export จาก Canva ก็ตาม เป็นไปได้ว่า:
- เทมเพลต/องค์ประกอบที่ใช้ไม่รองรับการส่งออกแบบโปร่งใส (ฟีเจอร์นี้ของ Canva ใช้ได้กับบางอิลิเมนต์เท่านั้น ไม่ใช่ทุกวิดีโอทั้งไทม์ไลน์)
- หรือตอน export เลือกฟอร์แมตเป็น MP4 ซึ่ง MP4 **ไม่รองรับความโปร่งใสในตัวมันเองอยู่แล้ว** ไม่ว่าจะตั้งค่ายังไงก็ตาม (ต้อง export เป็น .mov หรือ .webm ถึงจะเก็บอัลฟ่าไว้ได้)

ไฟล์ MP4/WebM ที่ส่งมาจึงไม่มีทางทำให้โปร่งใสย้อนหลังได้ — ต้องได้ไฟล์ต้นฉบับที่มีอัลฟ่าจริงๆ เท่านั้น

**ถ้าอยากได้แบบโปร่งใสจริง:** ลองเช็คใน Canva ว่าตอนกด Download มีตัวเลือก "พื้นหลังโปร่งใส / Transparent background" ให้ติ๊กไหม (ปกติต้องใช้ Canva Pro และใช้ได้กับดีไซน์บางประเภทเท่านั้น) ถ้ามี ให้เลือก format เป็น **.mov** (คุณภาพอัลฟ่าดีที่สุด) แล้วส่งไฟล์ใหม่มา จะเอามาทำเป็น WebM-อัลฟ่าสำหรับเว็บให้

**ในทางปฏิบัติตอนนี้:** วิดีโอที่ใช้อยู่ฉากกลางเป็นพื้นขาว ต้น-ท้ายเป็นสีดำ ซึ่งพอวางทับหน้าเว็บพื้นขาวแล้วมันกลืนไปกับพื้นหลังเว็บได้ค่อนข้างเนียนอยู่แล้ว (ดูจากภาพตัวอย่างตอนทดสอบ) เลยยังไม่มีปัญหาเรื่องภาพหลุดหรือขอบเห็นชัดตอนนี้

## การ์ด YouTube (ยอดผู้ติดตาม + วิดีโอล่าสุด)
ตอนนี้ในหน้าหลักจะมีการ์ดใหม่ใต้ปุ่มทั้ง 4 ปุ่ม แสดง:
- รูปโปรไฟล์ช่อง + ชื่อช่อง
- จำนวนผู้ติดตาม (ย่อเป็น K/M อัตโนมัติ)
- รูปย่อ + ชื่อวิดีโอล่าสุด กดแล้วไปดูใน YouTube ได้เลย

ถ้ายังไม่ได้ตั้ง `YOUTUBE_API_KEY` การ์ดนี้จะ**ซ่อนตัวเองไปเงียบๆ** ไม่ทำให้หน้าเว็บพัง

### วิธีขอ YouTube Data API v3 key (ฟรี)
1. ไปที่ https://console.cloud.google.com/
2. สร้างโปรเจกต์ใหม่ (หรือใช้โปรเจกต์เดิมก็ได้)
3. เมนูซ้าย → **APIs & Services** → **Library** → ค้นหา **"YouTube Data API v3"** → กด **Enable**
4. ไปที่ **APIs & Services** → **Credentials** → **Create Credentials** → **API key**
5. คัดลอกคีย์ที่ได้ไปใส่ในตัวแปร `YOUTUBE_API_KEY` บน Render (แท็บ Environment)

โควตาฟรีต่อวันเยอะพอสมควร (10,000 หน่วย/วัน) และโค้ดมีแคชผลลัพธ์ไว้ 10 นาทีต่อครั้งอยู่แล้ว จึงไม่ต้องกังวลเรื่องโควตาหมด

## แก้ไข/เพิ่มลิงก์ภายหลัง
- แก้ไขไฟล์ใน `public/index.html` และ `public/menu.html` (มองหา `<a class="btn ...">`)
- ปุ่มที่ลิงก์ไปหน้าอื่นในเว็บเดียวกัน ต้องมี `data-transition="true"` ในแท็ก `<a>` เพื่อให้เล่นวิดีโอทรานซิชันก่อนเปลี่ยนหน้า ส่วนลิงก์ออกเว็บนอกไม่ต้องใส่

## ต่อยอดทำบอท (เช่น Discord bot) ในโปรเจกต์เดียวกัน
1. `npm install discord.js` (หรือไลบรารีบอทที่ต้องใช้)
2. สร้างไฟล์ `bot.js` แยกไว้ เขียนโค้ดบอทตามปกติ
3. เปิดไฟล์ `server.js` แล้วเพิ่มบรรทัด `require('./bot.js');` เพื่อให้บอทเริ่มทำงานพร้อมเว็บ

ถ้าบอทมีงานหนักหรืออยากให้แยกกันชัดเจนไม่กระทบกัน แนะนำสร้างเป็น Render service แยกอีกตัวแบบ **Background Worker** สำหรับรันบอทโดยเฉพาะจะเสถียรกว่า
