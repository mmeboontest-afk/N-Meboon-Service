# N'Meboon Menu Link (Web Service version)

เว็บลิงก์รวมโซเชียลของ N'Meboon พร้อมวิดีโอทรานซิชันตอนเปลี่ยนหน้า (มีเสียง)
และการ์ดแสดงยอดผู้ติดตาม + วิดีโอล่าสุดจาก YouTube

## โครงสร้างไฟล์
```
server.js            เซิร์ฟเวอร์ Express (จุดเริ่มโปรแกรม) + /api/youtube
package.json         รายชื่อ dependency + คำสั่ง start
public/
  index.html          หน้าหลัก (Youtube, Discord, Tiktok, Menu Link, การ์ด YouTube)
  menu.html           หน้าเมนูอื่นๆ (Roblox, Suno, Facebook, กลับหน้าหลัก)
  style.css           สไตล์ทั้งเว็บ
  script.js           ระบบทรานซิชันวิดีโอ + อนิเมชันปุ่ม + ดึงข้อมูล YouTube
  assets/             ไฟล์วิดีโอทรานซิชัน (.mp4 / .webm มีเสียงแล้ว)
```

## วิธี deploy บน Render (Web Service)

1. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ขึ้น GitHub repo **โดยให้ `server.js` และ `package.json` อยู่ที่ root ของ repo เลย** (ห้ามมีโฟลเดอร์ครอบอีกชั้น เช่น repo/nmeboon-website/server.js — ถ้า push ผิดชั้นแบบนี้ Render จะหา `package.json` ไม่เจอและเว็บจะขึ้น "Not Found")
2. เข้า https://dashboard.render.com → **New** → **Web Service**
3. เชื่อมกับ repo ที่เพิ่งสร้าง
4. ตั้งค่า:
   - **Runtime:** Node
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
5. ไปที่แท็บ **Environment** เพิ่มตัวแปร (ดูวิธีขอ API key ด้านล่าง):
   - `YOUTUBE_API_KEY` = ใส่คีย์ที่ขอมา
   - `YOUTUBE_HANDLE` = `NongMeboon` (ใส่หรือไม่ใส่ก็ได้ ค่าเริ่มต้นเป็นอันนี้อยู่แล้ว)
6. กด **Create Web Service** / **Manual Deploy** รอ build เสร็จ

## แก้ปัญหา "Not Found"
อาการนี้เกือบทั้งหมดเกิดจาก 1 ใน 3 ข้อนี้:
1. **โครงสร้างโฟลเดอร์ผิดชั้น** — `server.js` ต้องอยู่ที่ root ของ repo ไม่ใช่ในโฟลเดอร์ย่อย (เช็คได้จากแท็บ "Root Directory" ในหน้า Settings ของ service ว่าตรงกับที่ไฟล์อยู่จริงไหม)
2. **ตั้ง Service ผิดประเภท** — ถ้าสร้างเป็น "Static Site" ไว้ก่อนหน้านี้ แล้วมาใส่ `server.js`/`package.json` เพิ่ม จะไม่ทำงาน ต้องลบแล้วสร้างใหม่เป็น **Web Service** เท่านั้น
3. **Deploy ล้มเหลว** — เข้าไปที่แท็บ **Logs** ของ service ดูว่ามี error สีแดงตอน build หรือตอน start ไหม (เช่น `Cannot find module 'express'` แปลว่า build ไม่ผ่าน หรือลืมกด Manual Deploy หลังแก้โค้ด)

ถ้าเช็คแล้วยังไม่หาย ส่ง screenshot ของแท็บ **Logs** มาให้ดูได้เลย จะวิเคราะห์ให้ตรงจุดกว่านี้

## เรื่องเสียงในวิดีโอทรานซิชัน
ใส่เสียงกลับเข้าไปในวิดีโอให้แล้ว แต่มีข้อจำกัดจากตัวเบราว์เซอร์เองที่ควรรู้ไว้:
- **ตอนกดปุ่มเปลี่ยนหน้าในเว็บเดียวกัน** (เช่น "Menu Link | Other") **เสียงจะเล่นแน่นอน** เพราะเป็นการกดของผู้ใช้จริง เบราว์เซอร์อนุญาต
- **ตอนเปิดเว็บครั้งแรก/เข้าใหม่ตรงๆ** เบราว์เซอร์ (Chrome, Safari, Firefox ทุกตัว) จะ**บล็อกไม่ให้วิดีโอเล่นเสียงอัตโนมัติ**โดยไม่มีการโต้ตอบจากผู้ใช้ก่อน — นี่คือกฎของเบราว์เซอร์เอง ไม่ใช่ข้อจำกัดของโค้ด ไม่มีเว็บไหนเลี่ยงได้ 100%
- เพื่อแก้ปัญหานี้ ได้ทำปุ่ม 🔈 เล็กๆ มุมขวาล่างไว้ให้ ถ้าเบราว์เซอร์บล็อกเสียง วิดีโอจะยังเล่นภาพต่อได้ปกติ (แค่ไม่มีเสียง) แล้วปุ่มนี้จะโผล่มาให้กดเปิดเสียงเอง

## เรื่องพื้นหลังโปร่งใส (สำคัญ ขอชี้แจงตรงๆ)
เช็คไฟล์วิดีโอต้นฉบับที่ส่งมาอีกรอบแล้ว พบว่า**ไฟล์ไม่มีช่องอัลฟ่า (alpha channel) อยู่เลย** — คือมันเป็นวิดีโอทึบแสงปกติ (พื้นหลังจริงๆ เป็นสีดำ/สีขาวสลับกันไปตามแต่ละช่วง) ไม่ใช่ไฟล์โปร่งใสตั้งแต่ต้น แม้จะตั้งใจเลือกออปชันโปร่งใสตอน export จาก Canva ก็ตาม เป็นไปได้ว่า:
- เทมเพลต/องค์ประกอบที่ใช้ไม่รองรับการส่งออกแบบโปร่งใส (ฟีเจอร์นี้ของ Canva ใช้ได้กับบางอิลิเมนต์เท่านั้น ไม่ใช่ทุกวิดีโอทั้งไทม์ไลน์)
- หรือตอน export เลือกฟอร์แมตเป็น MP4 ซึ่ง MP4 **ไม่รองรับความโปร่งใสในตัวมันเองอยู่แล้ว** ไม่ว่าจะตั้งค่ายังไงก็ตาม (ต้อง export เป็น .mov หรือ .webm ถึงจะเก็บอัลฟ่าไว้ได้)

ไฟล์ MP4/WebM ที่ส่งมาจึงไม่มีทางทำให้โปร่งใสย้อนหลังได้ — ต้องได้ไฟล์ต้นฉบับที่มีอัลฟ่าจริงๆ เท่านั้น

**ถ้าอยากได้แบบโปร่งใสจริง:** ลองเช็คใน Canva ว่าตอนกด Download มีตัวเลือก "พื้นหลังโปร่งใส / Transparent background" ให้ติ๊กไหม (ปกติต้องใช้ Canva Pro และใช้ได้กับดีไซน์บางประเภทเท่านั้น) ถ้ามี ให้เลือก format เป็น **.mov** (คุณภาพอัลฟ่าดีที่สุด) แล้วส่งไฟล์ใหม่มา จะเอามาทำเป็น WebM-อัลฟ่าสำหรับเว็บให้

**ในทางปฏิบัติตอนนี้:** วิดีโอที่ใช้อยู่ฉากกลางเป็นพื้นขาว ต้น-ท้ายเป็นสีดำ ซึ่งพอวางทับหน้าเว็บพื้นขาวแล้วมันกลืนไปกับพื้นหลังเว็บได้ค่อนข้างเนียนอยู่แล้ว (ดูจากภาพตัวอย่างตอนทดสอบ) เลยยังไม่มีปัญหาเรื่องภาพหลุดหรือขอบเห็นชัดตอนนี้

## การ์ด YouTube (ยอดผู้ติดตาม + วิดีโอล่าสุด)
ตอนนี้ในหน้าหลักจะมีการ์ดใหม่ใต้ปุ่มทั้ง 4 ปุ่ม แสดง:
- รูปโปรไฟล์ช่อง + ชื่อช่อง
- จำนวนผู้ติดตาม (ย่อเป็น K/M อัตโนมัติ)
- รูปย่อ + ชื่อวิดีโอล่าสุด กดแล้วไปดูใน YouTube ได้เลย

ถ้ายังไม่ได้ตั้ง `YOUTUBE_API_KEY` การ์ดนี้จะ**ซ่อนตัวเองไปเงียบๆ** ไม่ทำให้หน้าเว็บพัง

### วิธีขอ YouTube Data API v3 key (ฟรี)
1. ไปที่ https://console.cloud.google.com/
2. สร้างโปรเจกต์ใหม่ (หรือใช้โปรเจกต์เดิมก็ได้)
3. เมนูซ้าย → **APIs & Services** → **Library** → ค้นหา **"YouTube Data API v3"** → กด **Enable**
4. ไปที่ **APIs & Services** → **Credentials** → **Create Credentials** → **API key**
5. คัดลอกคีย์ที่ได้ไปใส่ในตัวแปร `YOUTUBE_API_KEY` บน Render (แท็บ Environment)

โควตาฟรีต่อวันเยอะพอสมควร (10,000 หน่วย/วัน) และโค้ดมีแคชผลลัพธ์ไว้ 10 นาทีต่อครั้งอยู่แล้ว จึงไม่ต้องกังวลเรื่องโควตาหมด

## เรื่อง "AI" ที่ใช้ตอบคำถาม — พูดตรงๆ ว่าทำอะไรได้แค่ไหน
ตามที่ขอว่าไม่พึ่ง AI ภายนอกเลย ไปค้นดูใน GitHub แล้วพบว่าโปรเจกต์ FAQ bot ที่ไม่ใช้ AI ภายนอกจริงจังส่วนใหญ่ใช้เทคนิคเดียวกันคือ **TF-IDF + Cosine Similarity** (ตัดคำให้เหลือรากศัพท์ก่อน แล้ววัดว่าคำถามกับแต่ละหัวข้อในคลังความรู้ "คล้ายกันแค่ไหน" ด้วยคณิตศาสตร์) จึงเขียนเวอร์ชันนี้ให้ใหม่ ฉลาดกว่าการเทียบคำตรงๆ แบบเดิมชัดเจน เพราะ:
- จับคำที่ผันรูปได้ (allow/allowed/allowing → รากเดียวกัน)
- ให้น้ำหนักคำที่ "เฉพาะเจาะจง" มากกว่าคำทั่วไป แทนที่จะนับจำนวนคำซ้ำเฉยๆ
- ยังไม่ได้เรียกใช้ ChatGPT/Claude หรือ AI ภายนอกใดๆ เลยตามที่ต้องการ 100%

ทดสอบกับคำถามที่คุณลองจริงในรอบก่อน (What is Chat, Where is chat, Help, Ai) ตอนนี้ตอบได้แล้วเกือบทั้งหมด (เพิ่มหัวข้อทักทาย/แนะนำตัวบอท/รายการคำสั่งเข้าไปในคลังความรู้ด้วย)

**สิ่งที่ทำได้ดีขึ้น:** จับคำถามที่เขียนต่างไปจากที่เตรียมไว้ได้กว้างขึ้นกว่าเดิมมาก ตอบคำถามทักทาย/ถามว่าเป็นบอทแบบไหน/ขอบคุณ ได้แล้วด้วย
**สิ่งที่ยังทำไม่ได้ (ข้อจำกัดของวิธีนี้เอง ไม่ใช่บั๊ก):** ไม่เข้าใจความหมายแบบ AI จริง เช่นถ้าใช้คำที่ไม่มีในคลังความรู้เลย (เช่นถามว่า "name" แทน "nickname") อาจจับคู่ผิดหรือไม่มั่นใจได้ ไม่มีความจำการสนทนาต่อเนื่อง — ถ้าอยากได้ระดับ ChatGPT จริงๆ ต้องใช้โมเดลภาษาที่ฝึกมาแล้วซึ่งจะเป็น "AI ตัวอื่น" ตามที่บอกว่าไม่อยากพึ่ง

**คลังความรู้แก้ไขเองได้ที่ไฟล์ `faqKnowledgeBase.json`** เป็นไฟล์ JSON ธรรมดา เพิ่มหัวข้อใหม่ได้ตามรูปแบบนี้:
```json
{
  "id": "unique-id-อะไรก็ได้",
  "keywords": ["คำ", "ที่คาดว่าคนจะถาม"],
```

## วิธีตั้งค่าบอทให้ใช้งานได้จริง

### 1) สร้างบอทใน Discord Developer Portal
1. ไปที่ https://discord.com/developers/applications → **New Application** ตั้งชื่อ (เช่น N'Meboon AI)
2. ไปแท็บ **Bot** (ถ้ายังไม่มี bot user ให้กด Add Bot)
3. เปิด **Privileged Gateway Intents** → ติ๊กเปิดทั้ง 2 อัน:
   - **SERVER MEMBERS INTENT** (จำเป็น เพราะบอทต้องให้ยศสมาชิก)
   - **MESSAGE CONTENT INTENT** (จำเป็น เพราะระบบ Level + ตรวจจับพฤติกรรม ต้องอ่านเนื้อหาข้อความ)

5. ไปแท็บ **General Information** คัดลอก **Application ID** มาเก็บไว้ (อันนี้คือค่า `DISCORD_CLIENT_ID`)

### 2) เชิญบอทเข้าเซิร์ฟเวอร์
ไปแท็บ **OAuth2 → URL Generator** เลือก:
- **Scopes:** `bot`, `applications.commands`
- **Bot Permissions:** อย่างน้อย `Send Messages`, `Embed Links`, `Manage Roles`, `Manage Messages`, `Manage Nicknames`, `Manage Channels`, `Use Slash Commands`, `Read Message History`, `Add Reactions`, `Mute Members`, `Connect`, `Speak`

คัดลอกลิงก์ที่ได้ไปเปิดในเบราว์เซอร์แล้วเลือกเซิร์ฟเวอร์เพื่อเชิญบอทเข้า

**ถ้าเชิญบอทไปแล้วตั้งแต่รอบก่อน (ไม่ต้องเชิญใหม่):** ไปที่ตั้งค่าเซิร์ฟเวอร์ → Roles → เลือกยศของบอท → เปิดสิทธิ์เพิ่ม **Manage Messages**, **Manage Nicknames**, **Manage Channels** (สำหรับลบ GIF/ลิงก์, เปลี่ยนชื่อเล่นแสดง Level, และสร้างห้องถามคำถามชั่วคราว) ส่วน **MESSAGE CONTENT INTENT** ต้องไปเปิดในหน้า Developer Portal ตามข้อ 3 ด้านบน แล้ว Render จะ deploy ใหม่เองไม่ต้องทำอะไรเพิ่ม

**⚠️ ข้อจำกัดเรื่องชื่อเล่น:** Discord ไม่อนุญาตให้บอทเปลี่ยนชื่อเล่นของ **เจ้าของเซิร์ฟเวอร์ (Owner)** ได้ไม่ว่ากรณีใด (กฎของแพลตฟอร์ม ทุกบอทติดเหมือนกันหมด) และยศของบอทต้องอยู่ "สูงกว่า" ยศของสมาชิกคนนั้นด้วยถึงจะเปลี่ยนชื่อเล่นได้ ถ้าเจอ error ในชื่อเล่นของใครบางคน ให้เช็ค 2 ข้อนี้ก่อน

## 🔍 ถ้าเพลงยังไม่เล่นหลัง deploy รอบนี้ — เช็ค log ตามนี้
เพิ่ม log ละเอียดขึ้นมากให้แล้ว เปิด Render Logs แล้วหาบรรทัดพวกนี้ตามลำดับ:
```
[bot] Setting up music channel ...
[bot] Music channel found: #...
[music] Joining voice channel ...
[bot] X human member(s) currently in the music channel.
[music] start() called ...
[music] Playlist has 5 track(s): [...]
[music] Spawning ffmpeg: ...
[music] player.play() called.
[music] Voice connection state: ready
[music] Player state: Playing
```
ถ้า log หยุดอยู่แค่บรรทัดไหน หรือมี error โผล่มา (`ffmpeg exited with code...`, `ffmpeg stderr`, `AudioPlayer error`) **ส่ง log ช่วงนั้นมาให้ดูได้เลย** จะรู้ทันทีว่าติดตรงไหน — จุดที่มีโอกาสสูงสุดคือขั้นตอน `npm install` ของ `opusscript`/`@discordjs/voice` บน Render (เช็คใน log ตอน build ว่าผ่านไหม) เพราะจุดนี้ผมทดสอบจริงในนี้ไม่ได้ตามที่บอกไว้ตั้งแต่แรก

**Crossfade ทำงานยังไง:** ใช้ฟีเจอร์ `acrossfade` ของ FFmpeg (เครื่องมือมาตรฐานสำหรับตัดต่อเสียง ไม่ได้เขียนผสมเสียงเองแบบเสี่ยงๆ) เชื่อมทุกเพลงในคิวเป็นสตรีมเดียว โดยเพลงจะค่อยๆ เฟดเข้าออกทับกัน 3 วินาทีตรงรอยต่อพอดีตามที่ขอ เล่นจบครบคิวแล้ววนกลับมาเล่นใหม่ตั้งแต่ต้นอัตโนมัติ

## ⚠️ ทดสอบด้วยเพลงจริงที่ส่งมาแล้ว แต่ยังมีข้อจำกัดที่ต้องรู้
ผมทดสอบ pipeline นี้กับไฟล์เพลงจริงทั้ง 5 เพลงที่คุณส่งมาแล้วจริงๆ (รันผ่าน FFmpeg จริง วัดความยาวไฟล์ผลลัพธ์ตรงกับคณิตศาสตร์ที่คำนวณไว้เป๊ะ เช็คระดับเสียงตรงรอยต่อไม่มีเสียงเงียบ/แตก) — แนบไฟล์ตัวอย่าง `crossfade-preview.mp3` มาให้ลองฟังได้เลยว่าเสียงที่ได้เป็นแบบนี้

**สิ่งที่ยังทดสอบไม่ได้ในสภาพแวดล้อมนี้ (ไม่มีลำโพง/ไมค์/การเชื่อมต่อ Discord voice จริง):**
- การเชื่อมต่อ Discord Voice Gateway จริง (join ห้องเสียงจริง ส่งเสียงจริง)
- ว่า `opusscript` + `libsodium-wrappers` จะติดตั้งและทำงานลื่นไหลบน Render จริงไหม
- คุณภาพเสียงตอนฟังผ่านหูจริงๆ ใน Discord (คุณภาพของไฟล์ที่ผมแนบมาควรจะเหมือนกันเป๊ะ เพราะใช้ pipeline เดียวกัน)

**ถ้าเสียงมีปัญหาหลัง deploy** (ไม่มีเสียง, เสียงขาดๆ หายๆ, บอทเข้าห้องไม่ได้) ส่ง Render Logs มาให้ดูได้เลย จุดที่เสี่ยงที่สุดคือขั้นตอน `npm install` ของ `opusscript`/`ffmpeg-static`/`@discordjs/voice` — ถ้า build fail ตรงนี้ ส่ง log มาดูได้ทันที

**⚠️ สำคัญมาก:** หลังเชิญเข้าแล้ว ไปที่ตั้งค่าเซิร์ฟเวอร์ → Roles → **ลากยศของบอท (เช่น 🤖 BOT / AI) ให้อยู่ "สูงกว่า" ยศ ✅ VERIFIED**เสมอ ไม่งั้นบอทจะให้ยศ Verified กับใครไม่ได้เลย (ติด role hierarchy ของ Discord เอง)

### 3) หา Guild ID (ไอดีเซิร์ฟเวอร์)
เปิด Discord → Settings → Advanced → เปิด **Developer Mode** → คลิกขวาที่ไอคอนเซิร์ฟเวอร์ → **Copy Server ID** อันนี้คือค่า `DISCORD_GUILD_ID` (ใส่ค่านี้ไว้ช่วยให้ `/summon` ขึ้นทันทีหลัง deploy ไม่ต้องรอนานเป็นชั่วโมงแบบลงทะเบียนคำสั่งแบบ global)

### 4) ตั้งค่า Environment Variables บน Render
ไปแท็บ **Environment** ของ Web Service เดิม (ตัวเดียวกับเว็บไซต์) เพิ่ม:

| ตัวแปร | ค่า |
|---|---|
| `MAIN_DISCORD_TOKEN` | token จากขั้นตอนที่ 1 |
| `DISCORD_CLIENT_ID` | Application ID จากขั้นตอนที่ 1 |
| `DISCORD_GUILD_ID` | Server ID จากขั้นตอนที่ 3 |
| `SITE_MENU_URL` | ลิงก์เว็บหน้า Menu ของคุณ (ใช้ในปุ่ม 📋 Menu ของการ์ด) |
| `SITE_VERIFY_URL` | ลิงก์ที่อยากให้ปุ่ม ✅ Verify ชี้ไป |

กด **Manual Deploy** อีกครั้งหลังตั้งค่าเสร็จ เปิด **Logs** ดูว่าขึ้น `[bot] Logged in as ...` และ `[bot] Slash commands registered to guild (instant).` ไหม ถ้าขึ้นแปลว่าใช้งานได้แล้ว ลองพิมพ์ `/summon information` ในเซิร์ฟเวอร์ได้เลย

## หมายเหตุเรื่อง OTP
- OTP เก็บไว้ใน**หน่วยความจำของบอท (RAM)** เท่านั้น ถ้า Render restart บอท (redeploy, sleep/wake, crash) รหัสที่ค้างอยู่จะหายไป ต้องกด Verify My Account ขอรหัสใหม่ — เหมาะกับการทดลองใช้งานตอนนี้ ถ้าจะเอาขึ้นจริงจังในอนาคตแนะนำเก็บลงฐานข้อมูลแทน (บอกได้เดี๋ยวจัดให้)
- รหัสหมดอายุอัตโนมัติใน 10 นาที ปรับได้ที่ค่า `OTP_EXPIRY_MS` ในไฟล์ `otpStore.js`
- ปุ่ม **📧 Email Verify** ตอนนี้ยังเป็นแค่ข้อความ "เร็วๆ นี้" ไว้ก่อน (บอกมาได้เมื่อพร้อมทำหัวข้อนี้ต่อ)

# 📈 ระบบ Level / XP

ระบบนับ XP แบบเดียวกับ Minecraft (ยิ่ง Level สูง ยิ่งต้องใช้ XP เยอะขึ้นแบบทวีคูณ) เก็บไว้ในไฟล์ `levelSystem.js`

**วิธีได้ XP:**
- แชท 1 ข้อความ = 1 XP (ข้อความที่โดนลบ/เตือนจากระบบตรวจจับพฤติกรรม จะไม่ได้ XP)
- อยู่ใน Voice Channel = 10 XP ต่อ 1 นาที (เช็คทุก 60 วินาที ใครอยู่ในห้องเสียงตอนนั้นได้ XP ไปเลย)
- XP จากมินิเกมในเว็บ: ยังไม่ได้ทำ (รอไอเดียเกมจากคุณก่อน)

**Level ขึ้นแจ้งเตือนที่:** `<#1504461180863905932>` ข้อความรูปแบบ `<@ผู้ใช้> Up to Level X!!!` ตรงตามที่สั่งเป๊ะ

**อันดับ XP สูงสุด 50 อันดับ:** บอทเช็คทุกชั่วโมงว่าเข้าเดือนใหม่/ปีใหม่หรือยัง ถ้าใช่จะประกาศอันดับของเดือน/ปีที่ผ่านมาไปที่ช่องเดียวกับ Level-up โดยอัตโนมัติ แล้วรีเซ็ต XP ของรอบนั้นเป็น 0 (ไม่รีเซ็ต Level หรือ XP รวมทั้งหมด) รูปแบบข้อความ:
```
[1] <@ผู้ใช้> Level X XP X
[2] ...
```
ไม่รวมบอท และถ้ามีคนได้ XP ไม่ถึง 50 คน ก็จะแสดงเท่าที่มีจริง (ไม่โชว์อันดับว่าง)

**⚠️ ข้อมูล XP จะหายได้ (สำคัญมาก):** เก็บไว้ในไฟล์ธรรมดา (`data/levels.json`) ซึ่งอยู่บน filesystem ชั่วคราวของ Render — พอ service redeploy/restart/sleep-wake ข้อมูลจะ**รีเซ็ตเป็น 0 หมดทุกคน** เหมาะกับการทดลองใช้งานตอนนี้เท่านั้น ถ้าอยากให้ Level/XP อยู่ถาวรจริงจัง ต้องต่อฐานข้อมูลฟรีภายนอก (แนะนำ MongoDB Atlas free tier ซึ่งฟรีตลอดไป ไม่มีวันหมดอายุ) — บอกมาได้เดี๋ยวจัดการเปลี่ยนให้

**ปรับความยากของ Level ได้ — อัปเดตแล้วให้ยากขึ้นตามที่ขอ:** Level เดิมได้เร็วเกินไป (สูตร Minecraft ตรงๆ ออกแบบมาสำหรับเกมที่ได้ XP ทีละเยอะๆ ไม่เหมาะกับแชท 1 ข้อความ = 1 XP) เลยเพิ่มตัวคูณความยากเข้าไป ค่าเริ่มต้นตอนนี้ยากขึ้น **6 เท่า** จากเดิม (เช่น Level 1 จากเดิมต้องแชท 7 ข้อความ ตอนนี้ต้อง 42 ข้อความ, Level 10 จากเดิม 160 ข้อความ ตอนนี้ 960 ข้อความ)

**ปรับเองได้โดยไม่ต้องแก้โค้ด/deploy ใหม่** — ไปที่ Render → Environment → เพิ่มตัวแปร `LEVEL_XP_MULTIPLIER` ใส่ตัวเลขที่ต้องการ:
- `1` = สูตร Minecraft ดิบๆ (เร็วมากแบบเดิม)
- `6` = ค่าเริ่มต้นตอนนี้
- `12` = ยากขึ้นอีกเท่าตัวจากค่าเริ่มต้น

ใส่แล้วกด Manual Deploy ใหม่ ปรับเลขไปเรื่อยๆ จนกว่าจะรู้สึกว่าพอดีกับความถี่ในการแชทของเซิร์ฟเวอร์คุณ

**⚠️ หมายเหตุ:** ถ้าใครมี Level ค้างอยู่จากก่อนหน้านี้ (กรณีข้อมูลไม่โดนรีเซ็ตพอดี) พอ XP ที่มีอยู่ไม่พอสำหรับ Level เดิมภายใต้กฎใหม่ที่ยากขึ้น ระบบจะคำนวณ Level ใหม่ให้ตรงกับ XP จริงเสมอ (อาจเห็น Level ลดลงได้ในเคสนี้ ไม่ใช่บั๊ก แค่คำนวณใหม่ให้ตรงกับกฎล่าสุด) แต่ในทางปฏิบัติข้อมูล Level มักรีเซ็ตเป็น 0 อยู่แล้วทุกครั้งที่ Render redeploy (ตามที่อธิบายไว้ด้านบน) จึงไม่น่าจะเจอเคสนี้บ่อย

# 🛡️ ระบบตรวจจับพฤติกรรมอัตโนมัติ (Auto-Moderation)

ไฟล์ `moderation.js` — เป็นระบบตรวจจับแบบ **rule-based (จับคำ/รูปแบบ)** ไม่ใช่ AI จริงๆ จับกรณีชัดเจนได้ดี แต่ไม่เข้าใจบริบท/มุก/ภาษาที่บิดเบือน ถ้าเจอช่องโหว่ บอกมาได้จะเพิ่มคำ/เงื่อนไขให้

**ตรวจจับอะไรบ้าง:**
| พฤติกรรม | การกระทำ | อ้างอิงกฎ |
|---|---|---|
| ลิงก์ทุกชนิด (http/https) | ลบข้อความทันที **ไม่มีการเตือน** | Mid — "Links not allowed" |
| GIF (ไฟล์แนบ/embed/ลิงก์ tenor,giphy) | ลบข้อความทันที **ไม่มีการเตือน** | Low — "GIFs not allowed" |
| ส่งข้อความรัวๆ (≥5 ข้อความใน 5 วินาที) | เตือนที่ `<#1500139152098722053>` เป็นภาษาอังกฤษ | Low — "No spam" |
| แท็กเยอะเกิน (@everyone หรือแท็ก ≥4 คนในข้อความเดียว) | เตือนที่ช่องเดียวกัน | Low — "Ping not allowed" |
| คำหยาบ/เนื้อหารุนแรง/NSFW (ตาม keyword list) | เตือนที่ช่องเดียวกัน | High — "Violence/NSFW not allowed" |

ข้อความที่โดนลบ/เตือน จะไม่ได้ XP ด้วย

**เพิ่มคำที่อยากให้จับ:** แก้ array `NSFW_VIOLENCE_KEYWORDS` ในไฟล์ `moderation.js` ได้เลย

**ยังไม่ได้ทำ (ของเดิมที่เคยอธิบายไว้ในกฎ):** ระบบ "แต้มสะสม" ที่ทำให้มิวท์อัตโนมัติตามตาราง Penalty (Low <15pts → mute 3-60min ฯลฯ) — ตอนนี้แค่เตือนอย่างเดียว ยังไม่ได้ตัดแต้ม/มิวท์จริง เพราะเป็นฟีเจอร์ใหญ่แยกต่างหาก (ต้องเก็บแต้มสะสมต่อคน ต่อหมวด ตัดสินใจว่าเมื่อไหร่จะ mute นานแค่ไหน) บอกมาได้เดี๋ยวทำต่อให้ครับ
